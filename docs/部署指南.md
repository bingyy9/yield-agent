# 部署到国内云服务器

目标：在一台国内 Linux 云服务器上，用 **Nginx + Node + pm2** 跑起 FAgent，浏览器访问 `http://服务器IP` 就能演示。

## 0. 先看清一个前提：国内服务器上用不了 Claude

Anthropic 不向中国大陆（以及香港）提供 Claude API 服务，国内服务器也连不通 `api.anthropic.com`。所以服务器上**不要**配置 `ANTHROPIC_API_KEY`。剩下两种选择：

- **离线回放**：什么 Key 都不配，程序自动走回放。三条调查路径、所有工具计算、晶圆图和 8D 报告都是真实运行的，只是 AI 的「台词」是预先写好的，不能自由追问（见学习指南 3.5 节）。
- **国产大模型在线模式**：配上 DeepSeek、通义千问、智谱 GLM 或腾讯混元的 API Key 后，页头的「在线」就能选了，由国产模型实时决定调用哪些工具，可以自由追问。做法见第 4 步之后的「接国产模型」。

不管配没配 Key，页面打开时默认都是离线回放；要用大模型，得在页头手动切到「在线」。演示时可以先用回放稳稳走一遍，再切在线现场追问。

## 1. 选服务器

| 项 | 推荐 | 说明 |
| --- | --- | --- |
| 产品 | 腾讯云「轻量应用服务器」或阿里云 ECS | 轻量服务器带宽、流量打包，最省心 |
| 配置 | **2 核 4G** | `next build` 吃内存，2G 容易构建失败（见第 3 步的 swap） |
| 系统 | Ubuntu 22.04 / 24.04 LTS | 下面的命令都按 Ubuntu 写 |
| 地域 | 离观众最近的大陆地域 | 选香港可以免备案，但同样用不了 Claude API |

**腾讯云轻量服务器购买要点**（入口：<https://cloud.tencent.com/product/lighthouse>，或官网顶部「产品 → 计算 → 轻量应用服务器」）：

- 账号要先完成实名认证；
- 地域：选离观众近的大陆地域，比如广州、上海、北京；
- 镜像：选「**系统镜像 → Ubuntu 24.04 LTS**」，不要选宝塔、Node.js 这类应用镜像，后面的步骤是按纯净系统写的；
- 套餐：2 核 4G；
- 登录方式：设置密码或绑定 SSH 密钥，默认用户名是 `ubuntu`；
- 买完以后，在实例详情页记下**公网 IP**。

**备案**：大陆服务器想用**域名**访问（80/443 端口），域名必须先做 ICP 备案，一般 1～3 周，云厂商提供免费代备案。只是演示的话，**直接用公网 IP 访问**就行，不需要备案。

**安全组 / 防火墙**：轻量服务器在实例详情页的「防火墙」标签页里设置，ECS 在「安全组」里设置。放行 **22**（SSH）和 **80**（以后上 HTTPS 再放 443）。**不要**放行 3000，Node 只让 Nginx 在本机访问。

## 2. 装 Node（服务器上）

Next.js 16 需要 Node 20.9 以上，用 22 LTS 即可。国内从 npmmirror 下载最快：

```bash
# 自动取 npmmirror 上最新的 Node 22（旧地址 npmmirror.com/mirrors/... 现在会 302 跳转，wget 下载会失败）
MIRROR=https://registry.npmmirror.com/-/binary/node/latest-v22.x
NODE=$(curl -s $MIRROR/ | grep -o "node-v22\.[0-9.]*-linux-x64\.tar\.xz" | sort -uV | tail -1 | sed "s/\.tar\.xz//")
echo $NODE        # 比如 node-v22.20.0-linux-x64
cd /tmp && curl -fLO $MIRROR/$NODE.tar.xz
sudo tar -xJf $NODE.tar.xz -C /opt && sudo ln -sf /opt/$NODE/bin/{node,npm,npx} /usr/local/bin/
node -v

# npm 换国内源，再装进程守护工具 pm2
npm config set registry https://registry.npmmirror.com
sudo npm i -g pm2 && sudo ln -sf /opt/$NODE/bin/pm2 /usr/local/bin/
```

## 3. 把代码传上去并构建

国内服务器访问 GitHub 不稳定，推荐**从你的 Mac 直接 rsync 上传**（在 Mac 的项目目录里执行）：

```bash
# 把 ubuntu@1.2.3.4 换成你的服务器
ssh ubuntu@1.2.3.4 "sudo mkdir -p /opt/yield-agent && sudo chown \$USER /opt/yield-agent"
rsync -az --delete --exclude node_modules --exclude .next --exclude .env.local ./ ubuntu@1.2.3.4:/opt/yield-agent/
```

然后在服务器上：

```bash
cd /opt/yield-agent
npm ci            # 按 package-lock.json 精确安装依赖
npm run build     # 生产构建
```

如果服务器只有 2G 内存、构建时报 `Killed` 或 `heap out of memory`，先加 2G swap 再构建：

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

字体已经随仓库提供（`src/app/fonts/`），构建时不需要访问 Google Fonts，国内服务器可以直接构建。

## 4. 用 pm2 让它常驻

```bash
cd /opt/yield-agent
pm2 start npm --name yield-agent -- start -- -H 127.0.0.1 -p 3000   # 只监听本机，外部经 Nginx 访问
pm2 save
sudo env PATH=$PATH:/usr/local/bin pm2 startup systemd -u ubuntu --hp /home/ubuntu   # 开机自启，服务器重启后自动拉起

curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/   # 返回 200 即正常
```

常用：`pm2 logs yield-agent` 看日志，`pm2 restart yield-agent` 重启。

### 可选：接国产模型，打开在线模式

先到所选厂商的控制台注册、实名、充值少量余额，创建一个 API Key。然后在服务器上写配置：

```bash
cat > /opt/yield-agent/.env.local <<'EOF'
LLM_PROVIDER=glm
LLM_API_KEY=你的key
EOF
chmod 600 /opt/yield-agent/.env.local     # Key 只给自己看
pm2 restart yield-agent                   # 只读环境变量，重启即可，不用重新构建
```

| 厂商 | LLM_PROVIDER | 默认模型 | 备注 |
| --- | --- | --- | --- |
| DeepSeek | `deepseek` | `deepseek-chat` | 便宜，工具调用稳，推荐先用它 |
| 阿里云百炼（通义千问） | `qwen` | `qwen-plus` | 兼容接口不支持「工具 + 流式」，默认非流式，文字按步出现而不是逐字出现 |
| 智谱 | `glm` | `glm-4.6` | |
| 腾讯混元 | `hunyuan` | `hunyuan-turbos-latest` | |

- 模型名各家更新很快，以控制台为准，用 `LLM_MODEL=...` 覆盖默认值。
- 重启后刷新页面，页头的「在线（模型名）」变成可点就说明配好了。
- `.env.local` 不会被第 3、7 步的 rsync 覆盖（已经 `--exclude`），更新代码时不用重新配。
- 页面上看到「API key 无效」「模型不可用」等报错时，对照提示检查 `LLM_API_KEY`、`LLM_MODEL`；`pm2 logs yield-agent` 里也能看到配置错误。

## 5. 配 Nginx（流式输出的关键在这一步）

```bash
sudo apt update && sudo apt install -y nginx
sudo tee /etc/nginx/sites-available/yield-agent >/dev/null <<'EOF'
server {
    listen 80;
    server_name _;               # 有备案域名后改成域名

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Agent 接口是 NDJSON 流：必须关掉缓冲，否则 Nginx 会攒满整段再发，页面变成等半天一次性出来
    location /api/agent {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_cache off;
        gzip off;
        proxy_read_timeout 300s;   # 和 route.ts 的 maxDuration 一致
    }
}
EOF
sudo ln -sf /etc/nginx/sites-available/yield-agent /etc/nginx/sites-enabled/yield-agent
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

浏览器打开 `http://服务器IP`，点一个异常批次，应该看到字一段段冒出来、工具卡片一张张出现。

> 为什么要关缓冲？回顾学习指南 4.7 节：浏览器靠「收一行处理一行」实现实时效果。Nginx 默认会先把后端响应攒进缓冲区再转发，流就被「憋」成了一整块。`proxy_buffering off` 和代码里的 `X-Accel-Buffering: no` 响应头都是为了防这个，双保险。

## 6. 可选：加个访问密码

演示地址不想被随便访问，可以加 Nginx 基础认证：

```bash
sudo apt install -y apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd demo        # 按提示输入密码
```

在上面配置的 `server { ... }` 里加两行，然后 `sudo nginx -t && sudo systemctl reload nginx`：

```nginx
    auth_basic "FAgent Demo";
    auth_basic_user_file /etc/nginx/.htpasswd;
```

## 7. 以后更新代码

在 Mac 上改完代码后：

```bash
rsync -az --delete --exclude node_modules --exclude .next --exclude .env.local ./ ubuntu@1.2.3.4:/opt/yield-agent/
ssh ubuntu@1.2.3.4 "cd /opt/yield-agent && npm ci && npm run build && pm2 restart yield-agent"
```

## 8. 排查

| 现象 | 原因与处理 |
| --- | --- |
| 浏览器打不开 | 安全组没放行 80；`sudo systemctl status nginx` 看 Nginx 是否在跑 |
| 502 Bad Gateway | Node 没起来：`pm2 logs yield-agent` 看报错 |
| 页面能开，但调查过程「卡住后一次性出来」 | Nginx 缓冲没关，检查 `/api/agent` 那段配置是否生效 |
| `npm run build` 被 Killed | 内存不够，按第 3 步加 swap |
| `npm ci` 很慢或超时 | 没换国内源，执行 `npm config set registry https://registry.npmmirror.com` |
| 配了 LLM_API_KEY 但页头「在线」点不了 | 改完 `.env.local` 没 `pm2 restart`；或 `LLM_PROVIDER` 拼错（看 `pm2 logs`）。注意默认就是离线回放，要手动切到「在线」 |
| 域名访问被拦截、提示未备案 | 大陆服务器的域名需要 ICP 备案，备案前先用 IP 访问 |
